Forms

How Keryx asks for input: where forms live, how they are laid out, when they validate, and how they save.

WCAG 2.2 AAComposes components

Overview

Keryx has two kinds of form. Short tasks (add or edit a source, create a key, add a topic) are a dialog with one to four fields. Settings is one long page form made of sections and saved by a save bar. There are no inline forms: editing always opens a dialog or a screen.

  • Every control sits in a form field: label above, help or error below.
  • One column. Two short related fields may share a row from 640 px.
  • One primary action per form.

Error summary → section → field error → save bar
  • Order: error summary (only after a failed submit), sections or fields in the order the task is done, actions last.
  • Dialog actions: ghost Cancel then the primary button, right-aligned.
  • Required is the default and unmarked; optional fields say “(optional)”.
  • Defaults: pre-fill everything Keryx knows; pre-select the common choice.

States

StateWhat happens
PristineSaved values. On Settings the save bar is absent.
DirtyThe save bar appears with Discard and Save changes. Leaving the page asks to confirm.
ValidatingA field validates on blur, and on every change once it has an error. The source URL is also test-fetched: a status alert reports the result.
Invalid on submitSummary appears and takes focus; each line links to its field; fields show their own errors; nothing is cleared.
SubmittingAll controls and Cancel disabled; the primary button is busy with “Saving…”; a dialog ignores Escape.
SavedA dialog closes and a toast confirms. Settings confirms in the save bar, with the consequence.
FailedA danger alert at the top of the dialog body (or the save bar) with a reference; everything re-enabled; entries kept.

Responsive behaviour

  • One column below 640 px; field grids and choice grids widen from 640 px; settings sections become two columns at 768 px.
  • A dialog form is a bottom sheet below 640 px with its footer always visible.
  • The save bar is sticky at every width and wraps; the form keeps 96 px of bottom padding so the bar never covers the focused field.
  • Controls are 44 px tall on touch devices.

Accessibility

  • <form novalidate> with Keryx's own messages, so wording and timing are consistent across browsers.
  • Every control has a visible <label>; groups use <fieldset> and <legend>.
  • Errors: aria-invalid="true" plus aria-describedby to the message; the summary is role="alert", focusable, and lists links to fields (WCAG 3.3.1, 3.3.3).
  • Enter in a text field submits; the busy state is announced through a polite status (“Saving your changes…”).
  • Destructive submits are confirmed; reversible changes offer Undo (WCAG 3.3.4).
  • Nothing entered is ever lost on error (WCAG 3.3.7).

Content

  • Labels are nouns; buttons are verbs; errors say how to fix and give an example.
  • Help text explains the consequence of a value, not the control.
  • Summary title: “Fix 2 fields to save your changes”. Each line: “Field: instruction.”
  • See the error formula.

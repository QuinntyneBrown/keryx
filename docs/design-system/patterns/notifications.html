Notifications

How Keryx tells staff that something happened without being asked: toasts, the navigation badge, the Overview, and e-mail alerts.

WCAG 2.2 AAComposes components

Overview

Keryx notifies in layers, from quiet to loud. A fact that will still be true in an hour lives on a screen (the Overview status card, the Runs badge). A fact about the last few seconds is a toast. Things that need someone who is not looking go out by e-mail, configured in Settings. There is no notification centre: the Runs screen is the history.

  • Toasts confirm; they are never the only record of something important.
  • A persistent problem is shown persistently, where it can be acted on.
  • One event, one notification.

When to use

EventChannel
The person's own action finishedToast
A run started, finished or failed while the admin is openToast; status card and badge update
Sources are failing nowCount on the Runs link; issue cards on Overview
Articles are waiting for reviewWarning count on the Needs review tab; an issue card
A source failed N runs in a rowE-mail alert (Settings › Alerts); a streak line on the issue
A whole run failedE-mail alert; danger toast if the admin is open; status card
A one-time secret was createdCallout, not a toast
ToneForLeaves
InfoSomething started or changed neutrallyAfter 8 s or more

DangerFailedOnly when dismissed or retried

Structure

Collection failed

Keryx couldn’t reach its database, so nothing was stored. The API is still serving the previous run.

Collection finished with 2 failing sources

47 new articles. Redeemed Run Club Toronto and Covenant Cycling Collective didn’t respond.

Collection started

Checking 64 sources. This usually takes about 4 minutes.

Three stacked: the newest at the bottom, the error without a countdown
  • Stack: at most three, 8 px apart, newest at the bottom. A fourth pushes the oldest out; errors are kept in preference to others.
  • Grouping: repeated events merge (“3 sources removed”) rather than queueing three toasts.
  • Action: one per toast. Undo, View run, Retry now.
  • Position: bottom right; offset above the save bar on Settings.
  • Priority: a danger toast is assertive and may interrupt; everything else is polite.

States

Toast stateBehaviour
EnteringSlides up and fades in.
ShowingCountdown bar runs.
PausedOn hover or focus inside.
PersistentDanger: no countdown.
LeavingFades; focus handed on.
StackedUp to three.

Responsive behaviour

  • Full width at the bottom below 640 px; 384 px bottom right above.
  • On phones add the bottom safe-area inset.
  • The Runs badge is visible in the top bar on small screens, so the count is never hidden with the sidebar footer.

Accessibility

  • Two live regions exist from page load: polite (role="status") and assertive (role="alert"); a toast is inserted into the right one (WCAG 4.1.3).
  • Toasts never take focus; their controls are reachable by Tab at the end of the page.
  • At least 8 seconds, paused on hover and focus, and errors persist (WCAG 2.2.1).
  • The badge's meaning is hidden text inside the link (“Runs, 2 failing sources”).
  • Nothing is conveyed by a toast alone: the same fact is on Overview or Runs.
  • E-mail alerts contain no tokens or keys and no private contact details.

Content

  • Title in the past tense, no full stop: “Source added”, “Collection failed”.
  • Text gives the consequence and the next fact.
  • Warnings name what failed; errors say what is still fine.
  • Action labels are one or two words.

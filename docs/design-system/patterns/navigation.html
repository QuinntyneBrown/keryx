Pattern

Navigation and page structure

How the admin is organised: six flat screens in one shell, a header on each, and details that open beside or above the list.

WCAG 2.2 AAComposes components

Overview

Keryx Admin is flat: six top-level screens reached from the sidebar, no nested routes. Each screen has a page header and a body. A record's details open in a panel beside the list; an edit opens in a dialog. The person never loses the list they were working in.

  • One primary navigation, always in the same order.
  • The URL changes for screens and for the selected record, so Back works and links can be shared.
  • System pages (sign in, access denied) have no navigation.

page body
Shell: sidebar (a top bar below 1024 px), page header, page body
  • Shell: skip link, sidebar, <main>. See app shell.
  • Page header: the h1, a live description, one primary action.
  • Page body: blocks stacked 24 px apart, each with a section head if there is more than one.
  • Templates: list page, dashboard with a rail, list with a detail panel, form page, system page; see layout.
  • Every route is lazy: screens load on demand, and their state lives on the routed component.

Responsive behaviour

  • Below 1024 px the sidebar is a top bar with sideways-scrolling links; there is no drawer and no menu button.
  • The detail panel covers the screen below 1024 px and is a column beside the table from there.
  • The Runs master–detail puts the run list above the detail below 1024 px and in a 340 px rail from there.
  • The page header's actions drop under the title below 640 px.

Accessibility

  • Landmarks: a skip link, <nav aria-label="Primary">, one <main>.
  • On navigation, focus moves to the new page's h1 and the document title changes (“Sources — Keryx”).
  • The current link has aria-current="page"; the count on Runs has hidden text for its meaning.
  • Navigation is identical on every screen (WCAG 3.2.3).
  • Opening a panel or dialog moves focus in; closing returns it to the row or button it came from.
  • The browser's Back button closes a panel before it leaves the screen.

Content

  • Screen names are one word and match the link, the title and the heading.
  • The page description carries live facts.
  • Document titles: “Screen — Keryx”; with a record, “Record · Screen — Keryx”.

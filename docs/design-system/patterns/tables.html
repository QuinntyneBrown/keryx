Data tables and lists

How Keryx shows many records: when a table, when a list, how they filter, page, select and shrink.

Overview

Keryx's data is long and paged: 18,432 articles, 64 sources, a run every six hours. Three tables and several lists show it. They never load a whole collection into the browser: the API pages every list, and so does the admin.

  • Filters sit above, the table in the middle, the range and paging below.
  • Rows are for scanning; the detail lives in a panel or another screen.
  • Newest or most urgent first, and the caption says which.

Showing 1–10 of 18,432 articles

Tabs, toolbar, table, footer: the Articles screen
  • Primary column: the record's name as a link, with a secondary line.
  • Sorting: fixed per table (articles newest first, sources failing first). There are no sortable headers yet; if added, use aria-sort and a button in the header.
  • Selection: single. A row opens the detail panel and is marked aria-current. There is no multi-select or bulk bar.
  • Row actions: one small ghost button, or a ••• menu for more, in a fixed-width last column.
  • Paging: Previous and Next with “Showing 1–10 of 18,432 articles” (pagination); no infinite scroll, so the footer and focus stay predictable and memory stays bounded.
  • Density: one. About 56 px per row; ten or twelve rows per page.

States

StateShown
LoadingSkeleton rows in the real columns; tabs and toolbar stay, disabled.
EmptyA first-run empty state replaces the table.
No resultsA compact empty state in the table's place; filters stay and keep their values.
ErrorAn error state with a reference and Try again.
Row hover / selectedSubtle fill / accent-subtle fill.
Row removedThe row leaves and a toast offers Undo or confirms.
PagingThe Next button is busy; current rows stay until the new page arrives.

Responsive behaviour

  • Below 1024 px a table shows its primary column and actions; status and context stack under the title. This is the “cards without cards” strategy: the markup stays a table.
  • With the detail panel open, optional columns give way first (1024–1535 px).
  • A table that still does not fit scrolls inside its wrapper; the page does not.
  • Tabs scroll sideways; filter chips wrap; the toolbar's selects wrap under the search field.

Accessibility

  • Tables are real <table>s with a caption that includes the order, and scope on headers.
  • Each row has at most two tab stops: its title link and its action.
  • The result range under the table is a polite live region, so filtering and paging are announced.
  • Status in a cell is text plus colour; scores are numbers plus a bar.
  • Aggregated titles are text with dir="auto"; source links open only http(s).
  • Hidden columns are hidden with display: none and their content is repeated in the stacked cell, so nothing is lost to anyone.

Content

  • Headers: one or two words, units included.
  • Em dash for an empty cell.
  • The footer names what is counted and reflects active filters.
  • Relative times up to a day, then dates.

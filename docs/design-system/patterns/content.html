Content and tone

How the voice rules apply across a whole flow, shown on one story: a run that finished with problems.

Overview

The content foundation sets the rules: plain, specific, calm, sentence case, numbers as numbers. This pattern shows them working together, because tone is judged across a flow, not a string. The same event is told five times at five sizes and must read as one voice.

  • The same fact uses the same words everywhere.
  • Each surface says only what fits its size and adds a way to the next.
  • Keryx is the subject of what Keryx did.

When to use

SurfaceLengthCarries
Navigation badgeA numberHow many need attention
ToastA title and a sentenceWhat just happened, one action
Status cardA headline and three numbersThe current state
Issue card and list rowA title, a source, a timeOne problem each
TimelineA line per stepWhere it went wrong
Detail (mono)The raw factFor whoever fixes it
E-mail alertA subject and three linesThe same headline, with a link

Structure

One run, told at each size:

Badge2

Collection finished with 2 failing sources

47 new articles. Redeemed Run Club Toronto and Covenant Cycling Collective didn’t respond.

Headline · Completed with 2 failing sources

Issue · Feed returned 404 · Redeemed Run Club Toronto · Today, 6:01 AM

Step · Fetch sources — 62 of 64 sources fetched · 2 failed

GET https://redeemedrun.ca/feed → 404 Not Found. The site may have moved its blog.

“2 failing sources” is the same phrase at every level
  • Vocabulary: collection or run (not job, sync or crawl); source (not feed or connector); article; held for review; published; hidden; consumer and key.
  • Status words: Published, Needs review, Hidden; Completed, Completed with issues, Failed, Running; Healthy, Failing.
  • Subject: “Keryx couldn’t…”, “Keryx will check…”, “Keryx stops checking…”.

States

StateVoice
WorkingPresent tense, a number: “Checking 64 sources.”
DonePast tense, the result: “47 new articles.”
ProblemWhat, where, since when: “Timed out after 30s · 4 runs in a row”.
FailureKeryx as subject, what is safe, what to do, a reference.
EmptyWhat is true, why, the first step.
DestructiveWhat stops, what is kept, whether it can be undone.

Responsive behaviour

  • Copy does not change with width; it wraps. Write it to fit 360 px.
  • Only meta lines truncate, and only when the full text is available elsewhere.
  • Buttons never wrap: three words at most.

Accessibility

  • Plain language helps everyone, and most of all people using translation or a screen reader.
  • Status words are text, never colour or icon alone.
  • Hidden text supplies what sighted users get from layout (“Error: ”, “(opens in a new tab)”).
  • Link and button text makes sense out of context.
  • Abbreviations are spelled out on first use on a screen, except those staff use daily (API, RSS, GTA, URL).

Content

  • Sentence case; no exclamation marks; curly quotes; Canadian spelling.
  • Numbers with separators; times in Toronto time.
  • Ids and URLs in mono.
  • See the microcopy library.

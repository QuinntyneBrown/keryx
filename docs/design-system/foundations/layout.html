Layout

Six breakpoints, a 4/8/12 grid, the named widths of the shell, and the five page templates.

WCAG 2.2 AALight and darkSource: tokens/tokens.css

Overview

The admin is a fixed ink sidebar and one fluid main column. Content is laid out with a few named widths (rail, panel, form) more than with a column grid, because every screen is a list, a table or a form. Layout values are tokens so they are the same decision everywhere.

Breakpoints

TokenWidthWhat changes
(base)0–639 pxOne column. Sidebar is a top bar. Dialogs are bottom sheets. Toasts span the bottom.
--layout-breakpoint-sm640 pxDialogs centre; toasts dock bottom right; page header becomes a row; field grids and choice grids widen.
--layout-breakpoint-md768 pxPage margin 32 px; card padding 24 px; settings sections become two columns; summary card becomes a row.
--layout-breakpoint-lg1024 pxThe sidebar appears; tables show all columns; rails sit beside content; the detail panel becomes a column.
--layout-breakpoint-xl1280 pxStatus card puts stats beside the summary; API list and code panel sit side by side.
--layout-breakpoint-2xl1536 pxTables keep every column even with the detail panel open.

Media queries use min-width in rem (40, 48, 64, 80, 96rem). Custom properties cannot be used inside @media, so the values are repeated there by convention; the tokens document them and feed tokens.json.

Page templates

See app shell for the classes and navigation and page structure for when to use which.

Usage

  • Grids use minmax(0, 1fr) tracks so long text cannot widen a column.
  • Full-height layouts use 100dvh.
  • Fixed bottom elements (toasts, the save bar) add env(safe-area-inset-bottom) on phones.
  • The page never scrolls horizontally; only a table wrapper, the tab list, the top-bar navigation and code blocks may.
  • A new screen picks an existing template; a new template needs a mock and an entry here.

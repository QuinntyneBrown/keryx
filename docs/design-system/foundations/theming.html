Theming

How light and dark are built from one set of semantic tokens, how to add a theme, and how to consume tokens.json.

Overview

Keryx has a light and a dark theme. The Magic Patterns design is light only; dark was derived from the same ink scale. A theme is a set of values for the semantic tokens; components never ask which theme is active.

How themes apply

  • Light is the default, declared on :root and on [data-theme="light"].
  • Dark applies with data-theme="dark" on <html> (or on any element, for a dark island), and automatically under prefers-color-scheme: dark unless the page forces data-theme="light".
  • Each theme sets color-scheme, so native controls, scrollbars and the select's option list follow.
  • prefers-contrast: more promotes borders to the strong colour and muted text to default.
  • forced-colors: active hands edges and selection to the system colours.
<html lang="en" data-theme="dark">   <!-- force dark -->
<html lang="en">                     <!-- follow the operating system -->
<div data-theme="light">…</div>      <!-- a light island inside a dark page -->

Token tiers

TierPrefixExampleWho may use it
Primitive--palette-*, --font-*--palette-volt-400Semantic tokens only.
Semantic--color-*, --text-*, --space-*, --size-*, --radius-*, --shadow-*, --duration-*, --ease-*, --z-*, --layout-*--color-accentComponents and pages. Themes override this tier.
Component--btn-*, --alert-*, --switch-*, --brand-*, --select-*--btn-bgOne component; declared in components.css; always aliases a semantic token.

  • Surfaces get lighter as they rise: canvas < surface < raised. The sidebar stays ink, one step darker than the canvas.
  • The accent flips from ink to volt, and text on it from paper to ink. Volt on a dark surface is the brand at its strongest; volt text on a light surface never happens.
  • Status backgrounds become deep tints with light text; solids and icons lighten.
  • The inverse surface (toasts) becomes paper, and its icon tokens flip back to the standard status colours.
  • Shadows get darker and stronger, but depth is carried mainly by surface colour.
  • Brand lockup colours do not change.

Adding a theme

[data-theme="partner"] {
  --color-accent: var(--palette-blue-700);
  --color-accent-hover: var(--palette-blue-950);
  --color-fg-on-accent: var(--palette-white);
  --color-focus-ring: var(--palette-blue-700);
  color-scheme: light;
}
  • Override semantic tokens only; add primitives if you need new raw values.
  • Add the theme's pairs to the contrast check: check_contrast.py reads every [data-theme] block.
  • Keep the two dark blocks in tokens.css identical (the data-theme one and the prefers-color-scheme one).
  • Never restyle a component per theme in components.css.

tokens.json

tokens/tokens.json is generated from tokens.css in the Design Tokens Community Group format: $type, $value, aliases as {palette.ink.950}, and dark overrides under $extensions. Regenerate it after any token change; never edit it by hand.

python .claude/skills/extracting-design-systems/scripts/tokens_to_json.py docs/design-system/tokens/tokens.css
python .claude/skills/extracting-design-systems/scripts/check_contrast.py docs/design-system/tokens/tokens.css

In the Angular workspace, tokens.css is a global foundation stylesheet; component stylesheets read tokens by role and never contain a hex value.

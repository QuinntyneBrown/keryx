Button

Buttons start something: run the collector, save settings, add a source, revoke a key. One primary button per view says what the screen is for.

Overview

Use a button when activating it changes something or opens a dialog. Use a link when it only goes somewhere, an icon button when there is no room for a label, and a menu when one trigger offers several actions.

  • Primary is the one action the view exists for (Run now, Add source, Save changes). It is ink in the light theme and volt in the dark theme.
  • Default (secondary) is every other action: Export CSV, Edit source, Cancel beside a destructive confirm.
  • Ghost has no edge. It is the quiet action inside a row or a footer: Mute, Revoke, Discard, Cancel in a form dialog.
  • Danger outlines a destructive action that still needs a confirmation; danger solid is the confirm button inside that confirmation dialog and nowhere else.

Anatomy

  1. Leading icon (optional)14 px (.icon--sm), inherits the label colour, aria-hidden. Replaced by the spinner while busy.
  2. Label--text-label (14 px medium), a verb phrase in sentence case; the accessible name.
  3. Container--control-height-md tall, --radius-md corners, hairline edge, --space-3 inline padding, --space-2 between icon and label.

Variants

Variants change emphasis, not meaning. Choose by how much attention the action deserves on this screen.

Sizes

Two sizes. Medium is the default; small lives inside table rows, list rows and pagination, where the row gives it room. There is no large size: on touch devices both grow to 44 px instead.

.btn--sm uses --control-height-sm; the default uses --control-height-md.

States

Every variant has the same states. Pointer and focus states are forced here with data-state; real pages get them from :hover, :focus-visible, :active, :disabled and aria-busy.

Both themes

  • Busy puts a spinner before the label, sets aria-busy="true" and disabled, and the label says what is happening (“Adding…”, “Saving…”). The other buttons in the same footer are disabled until it settles.
  • Disabled is the native attribute at --opacity-disabled. A button the user could reasonably expect to work stays enabled and explains itself on activation instead.
  • Active scales the button to 0.98; the primary button also darkens to --color-accent-active.

Responsive behaviour

  • Below 640 px the page header stacks and its actions sit under the title; they keep their natural width and wrap.
  • Dialog footers keep their buttons on one row, right-aligned, and wrap when the sheet is too narrow; the primary action stays last.
  • On touch devices (pointer: coarse) both sizes are 44 px tall. Nothing else changes.
  • A label never truncates and never wraps (white-space: nowrap). A label that does not fit at 360 px is too long: shorten the verb phrase.

Theming

The button reads four component tokens, --btn-bg, --btn-bg-hover, --btn-fg and --btn-border, that each variant sets from semantic tokens. The primary button follows --color-accent, which is ink in the light theme and volt in the dark theme with ink text on it: volt is never a text colour on a light surface.

/* Re-skin one variant without touching .btn */
.btn--primary { --btn-bg: var(--color-accent); --btn-bg-hover: var(--color-accent-hover); --btn-fg: var(--color-fg-on-accent); }

Accessibility

Role and pattern

A native <button type="button">, or type="submit" for the one submit of a form. No ARIA role is needed. See the WAI-ARIA button pattern.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter / SpaceActivates the button. Space fires on key up, so moving focus away cancels it.
EscNothing on the button itself; inside a dialog it closes the dialog unless the dialog is busy.

Focus

The shared ring (--focus-ring-width of --color-focus-ring, offset by --focus-ring-offset) appears on :focus-visible only, so a pointer click does not show it. It is ink in the light theme and volt in the dark theme, on the sidebar and on toasts. On the primary button the 2 px gap shows the surface colour, so the ring stays 3:1 against both the button and the page.

Labelling

The visible label is the accessible name. An icon-only button needs aria-label with the verb and its object (“Copy key”). A busy button keeps its name; the progress sentence is announced by the nearest status region, not by the button.

Motion

Background and colour change over --duration-fast; pressing scales to 0.98. Both are instant under reduced motion. The busy spinner turns once every --duration-spin and is stopped by the global reduced-motion rule; the label still says “Saving…”.

Touch

36 px tall with a fine pointer and 44 px (--target-comfortable) on touch devices, because --control-height-md grows under (pointer: coarse). Small buttons are 32 px with a fine pointer and sit at least 8 px apart.

Content

  • Verb first, sentence case, no full stop: “Run now”, “Add source”, “Save changes”, “Export CSV”.
  • Name the object when it is not obvious from the dialog title: “Remove source”, “Revoke key”, never “OK” or “Confirm”.
  • Busy labels are the same verb in progress with an ellipsis: “Adding…”, “Saving…”, “Removing…”.
  • Cancel is always “Cancel”; discarding edits is “Discard”.

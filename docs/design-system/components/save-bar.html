Save bar

A bar that sticks to the bottom of the Settings page while there are unsaved changes, with the form's two actions.

Overview

The save bar is the submit row of a long form. It appears when the form becomes dirty, stays in view however far the page is scrolled, and reports the result. Short forms in dialogs use the dialog footer instead.

  • It holds a status sentence on the left and Discard / Save changes on the right.
  • After a successful save it confirms in the same place, then leaves.

Anatomy

  1. StatusOne sentence; muted by default, success or danger tone with an icon when it reports a result.
  2. ActionsGhost Discard, primary Save changes.
  3. BarSurface with a hairline on top, position: sticky; bottom: 0, padded to the page margin.

Sizes

One size; its height follows its content and it wraps when narrow.

States

The bar is itself a state machine for the form.

StateStatus textActions
DirtyYou have unsaved changes.Discard · Save changes
SubmittingSaving your changes…Both disabled; Save is busy
Invalid2 fields need fixing before you can save.Discard · Save changes
SavedSaved at 9:46 AM, and what that changed.View runs
FailedKeryx couldn’t save your changes. Nothing was lost.Discard · Try again

Both themes

You have unsaved changes.

You have unsaved changes.

  • Hidden when the form is clean. It is added to the DOM when the first field changes.

Responsive behaviour

  • The text and the actions sit on one row when they fit and wrap, text first, when they do not.
  • It spans the main column, beside the sidebar from 1024 px, and is padded with --layout-margin.
  • The form has --space-24 of bottom padding so the bar never covers the last field or a focused control (WCAG 2.4.11).
  • On phones with a home indicator, add env(safe-area-inset-bottom) to its bottom padding.

Theming

It is a surface with a top hairline and no shadow, so in both themes it reads as part of the page, not a floating toast.

Accessibility

Role and pattern

A role="region" labelled “Unsaved changes” after the form in the DOM. Its text is a polite status while saving; the saved confirmation is role="status".

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter / SpaceActivates Discard or Save changes.
Enter in a fieldSubmits the form, the same as Save changes.

Focus

When it appears, focus stays where the person is editing. On a failed save, focus moves to the error summary at the top of the form; on success it stays on the page.

Labelling

The region label says why the bar is there. Discard asks for confirmation only when more than one field changed.

Motion

Nothing animates. The bar appears without sliding, so the page does not move under the pointer.

Touch

Its buttons are 36 px tall, 44 px on touch.

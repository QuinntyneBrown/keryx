Alert

A tinted message inside the page or a dialog, next to what it is about: why an article is held, what a test fetch found, why a save failed.

Overview

An alert stays where it is until the condition changes. Use it for a message that belongs to a place on the screen. For the result of an action that needs no place, use a toast; for a one-time value to copy, a callout; for a whole area that failed to load, an error state.

  • Five tones: info (default), success, warning, danger, neutral.
  • Optional title, list and actions.
  • The error summary at the top of a form is a danger alert with a list of links.

Anatomy

  1. Icon16 px, the tone's icon colour; decorative.
  2. BodyOptional title in --text-label, then text, a list or actions.
  3. ContainerTone background, --radius-md, --space-2-5 by --space-3 padding; no border.

Responsive behaviour

  • Fluid; text wraps beside the icon.
  • Actions wrap under the text.
  • Inside a centred container (the sign-in card) the body stays start-aligned.

Theming

Three component tokens, --alert-bg, --alert-fg and --alert-icon, set per tone from the status tokens: pale tint and dark text in light, deep tint and light text in dark.

.alert--warning { --alert-bg: var(--color-warning-bg); --alert-fg: var(--color-warning-fg); --alert-icon: var(--color-warning-icon); }

Accessibility

Role and pattern

Plain content by default. role="alert" only when it appears in response to an action and needs attention now (a failed save, the error summary); role="status" for a result that can wait (the test fetch).

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
EnterOn a summary link: moves focus to that field.

Focus

The error summary has tabindex="-1" and receives focus after a failed submit, so it is read at once and its links are next in the tab order.

Labelling

Tone is never the only signal: the text says what is wrong. Links inside an alert keep their underline and take the alert's text colour.

Content

  • Say what happened and what to do, in that order.
  • A failure says what was not lost (“Nothing changed.”) and gives a reference id in mono.
  • The error summary title counts: “Fix 2 fields to save your changes”; each line is “Field: how to fix it”.
  • No exclamation marks, no “Oops”, no blame.

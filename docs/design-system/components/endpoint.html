Overview

The endpoint row is an interactive list row on the API screen. Selecting one shows its example in the code panel beside the list.

  • Method in green semibold, path in mono, description beneath.
  • The selected endpoint is the current row.

Anatomy

  1. Method12 px semibold in --color-success-fg.
  2. SignatureMethod and path in --text-code-md.
  3. DescriptionA caption, muted.

Variants

  • GET/v1/articlesPublished articles, newest first. Filter by region, category, org, since.
  • GET/v1/articles/{id}One article with summary, tags and canonical link.
  • GET/v1/statusLast run time and pipeline health, for consumers to show freshness.

Responsive behaviour

  • Below 1024 px the list is above the code panel; from 1024 px they sit side by side (L2-067). The mocks' .split switches at 1280 px; the API screen lays out its own split at 1024 px.
  • Paths wrap at slashes if they must; descriptions wrap.

Theming

Only GET exists, so the method has one colour. It passes 4.5:1 on the row, the hovered row and the current row.

Accessibility

Role and pattern

A link row in a <ul>; the selected one has aria-current="true".

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
EnterShows that endpoint's example.

Focus

The shared ring (--focus-ring-width of --color-focus-ring, offset by --focus-ring-offset) appears on :focus-visible only, so a pointer click does not show it. It is ink in the light theme and volt in the dark theme, on the sidebar and on toasts.

Labelling

Read as “GET /v1/articles, Published articles, newest first…”. The method is text, not colour.

Content

  • The path exactly as the OpenAPI document has it, with {id} placeholders.
  • One sentence: what comes back and how it can be filtered.
  • The API is versioned; the version is in every path.

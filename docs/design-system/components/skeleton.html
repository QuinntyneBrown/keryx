Skeleton

Grey shapes in the layout of the content that is about to arrive, so the screen does not jump when it does.

Overview

Every screen has a loading state built from skeletons that mirror its real layout: the same cards, rows and columns with bars in place of text. They appear only if the first response takes longer than 300 ms.

  • Shapes: text line, title, stat, circle (status disc), icon, tile (source icon), pill (badge), chart, block.
  • Width helpers from 20 % to 80 % vary the lines so they read as text.

Anatomy

  1. Text lineA 12 px bar centred in one 21 px body line, so a skeleton paragraph is exactly as tall as the text that replaces it.
  2. ShapeMatches the element it stands for: a 44 px circle for the status disc, a 32 px tile for a source icon.

  • When data arrives the skeletons are swapped for content with no cross-fade; heights match, so nothing moves.

Responsive behaviour

  • Skeleton layouts use the same responsive containers as the real content, so they reflow identically.
  • Widths are percentages of their container.

Theming

A gradient between --color-bg-subtle-hover and --color-bg-subtle, visible on both the canvas and the surface in each theme.

Accessibility

Role and pattern

Skeletons are empty <span>s and are not announced. The container has aria-busy="true" and a visually hidden role="status" sentence: “Loading the overview…”.

Keyboard

KeyAction
—Not focusable. It is read in document order with the content around it.

Focus

Nothing is focusable while loading; the page header and navigation stay usable.

Labelling

One sentence per loading region, not one per skeleton.

Contrast

Shimmer (decorative)

Motion

A shimmer travels across every --duration-deliberate (1.4 s). Under reduced motion it stops and the shapes are a flat tint.

Touch

Not interactive, so no target size applies.

Content

  • The status sentence names the screen: “Loading the overview…”, “Loading articles…”.
  • No “Please wait”.

Drift fixed during extraction: a text skeleton was a 12 px bar with an off-grid 5 px margin above and below, 22 px in all, one pixel taller than the 21 px line it stands for. The margin is now derived from the line height, so skeleton and text match exactly; loading mocks are a few pixels shorter as a result. Other shape sizes were raw rem values and now come from tokens.

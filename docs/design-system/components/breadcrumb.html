Breadcrumb

The path from a top-level screen down to the page in view. Keryx is flat today, so no mock uses it.

Overview

All six screens are one level deep and details open in a panel or a dialog, so nothing needs a breadcrumb yet. It is defined for the day a run, a source or an organisation gets a page of its own. Until a mock calls for it, do not add one.

  • It sits above the page title, inside the page header.
  • The last item is the current page and is not a link to somewhere else.

Anatomy

  1. ListAn ordered list in a row; “/” separators drawn in CSS.
  2. Ancestor linkMuted, underlined on hover.
  3. Current pageDefault text colour, medium weight, aria-current="page".

Responsive behaviour

  • Below 768 px only the parent and the current page are shown; earlier ancestors are hidden.
  • Items wrap rather than truncate.
  • Links have a 24 px minimum line box.

Theming

It reads semantic tokens only, so both themes and prefers-contrast: more restyle it with no rule of its own.

Accessibility

Role and pattern

The WAI-ARIA breadcrumb pattern: <nav aria-label="Breadcrumb">, an <ol>, and aria-current="page" on the last link.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
EnterGoes to that ancestor.

Focus

The shared ring (--focus-ring-width of --color-focus-ring, offset by --focus-ring-offset) appears on :focus-visible only, so a pointer click does not show it. It is ink in the light theme and volt in the dark theme, on the sidebar and on toasts.

Labelling

The nav's label distinguishes it from the primary navigation. Separators are CSS content and are not read.

Content

  • Each item is the name of that page as its own title shows it.
  • Ids are shown as they are written elsewhere, in mono if they are in mono there.
  • Never more than three levels; deeper structure belongs in the page.

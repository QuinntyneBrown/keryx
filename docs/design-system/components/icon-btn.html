Icon button

A borderless square button for one familiar glyph: close a dialog, dismiss a toast, open the row menu.

WCAG 2.2 AAStatus: stableNative <button>Block: .icon-btn

Overview

Use it where a label would crowd the surface and the glyph is one people already know (×, •••). Anything less familiar gets a button with a label, or at least a tooltip.

  • Close in a dialog head and in the article panel head.
  • Dismiss on a toast, where it takes the toast's muted colour.
  • Row actions (•••) in the Sources table, where it is a menu button with aria-haspopup="menu".

Anatomy

  1. Glyph16 px icon (14 px on a toast), currentColor, aria-hidden.
  2. TargetA --control-height-sm square with --radius-md corners; transparent until hovered or expanded.

Variants

One look. What changes is the glyph and the ARIA it carries.

Close, row actions (menu button), dismiss
HTML
<button class="icon-btn" type="button" aria-label="Close">
<svg class="icon" aria-hidden="true" viewBox="0 0 24 24">…</svg></button>
<button class="icon-btn" type="button" aria-label="Actions for Grace Barbell Club" aria-haspopup="menu" aria-expanded="false">
<svg class="icon" aria-hidden="true" viewBox="0 0 24 24">…</svg></button>
<button class="icon-btn" type="button" aria-label="Dismiss">
<svg class="icon icon--sm" aria-hidden="true" viewBox="0 0 24 24">…</svg></button>

Sizes

One size: a 32 px square (<code>--control-height-sm</code>), 44 px on touch devices. The glyph is 16 px, or 14 px on a toast.

States

Hover and expanded share one look, so an open menu's trigger stays visibly pressed.

DefaultHoverFocusExpandedDisabled
Icon button

Both themes

  • Expanded is aria-expanded="true" on a menu button; it keeps the hover fill while the menu is open.
  • Disabled is used while a dialog is busy, so it cannot be closed mid-request.

Responsive behaviour

  • The target grows to 44 px on touch devices; the glyph stays 16 px.
  • In the article panel, which covers the screen below 1024 px, Close is the only way back besides Escape, so it is never hidden.
  • In table rows it sits in a fixed-width actions column (.table__col-actions) so the other columns do not shift.

Theming

It is transparent and takes --color-fg-muted; hover fills with --color-bg-subtle-hover. On a toast the glyph takes --color-fg-inverse-muted and the hover fill is dropped, because the toast is already the darkest surface.

Accessibility

Role and pattern

A native <button>. As a menu trigger it follows the WAI-ARIA menu button pattern: aria-haspopup="menu" and aria-expanded.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter / SpaceActivates: closes, dismisses, or opens the menu and moves focus to its first item.
ArrowDownOn a menu button, opens the menu.

Focus

The shared ring (--focus-ring-width of --color-focus-ring, offset by --focus-ring-offset) appears on :focus-visible only, so a pointer click does not show it. It is ink in the light theme and volt in the dark theme, on the sidebar and on toasts. When a dialog or panel closes, focus returns to the control that opened it.

Labelling

Always aria-label, naming the action and, in a table, the row: “Actions for Redeemed Run Club Toronto”, “Close article details”. “Close” alone is enough inside a dialog, whose title gives the context.

Contrast

Glyph on surface
Glyph on hover fill
Glyph on a toast

Motion

Colour changes run over --duration-fast (150 ms) with --ease-standard; the token is zero under prefers-reduced-motion, so the change is instant there.

Touch

32 px with a fine pointer and 44 px on touch devices: --control-height-sm grows to --target-comfortable under (pointer: coarse).

Content

  • The label is the action, not the picture: “Close”, not “X”; “Dismiss”, not “Cross”.
  • In repeated rows the label names the row, so a list of buttons read out of context still makes sense.
  • Never put a count or status in an icon button; use a badge beside it.

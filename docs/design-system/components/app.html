App shell

The frame every screen sits in: the ink sidebar, the main column, and optionally the article panel beside it.

WCAG 2.2 AAStatus: stableLandmarks: aside, nav, mainBlock: .app, .page-body

Overview

The shell places the sidebar and the <main> column, and gives the page body its margins. Three arrangements exist.

  • Default: sidebar and main. Below 1024 px they stack and the sidebar becomes a top bar.
  • Split (.app__main--split): main holds the content and a detail panel side by side, as on Articles.
  • Bare (.app--bare): no sidebar. Used before sign-in and for access denied, where there is nothing to navigate to.
  • Page body: .page-body applies the page margin; --form caps it at the form width; --centered centres one card for system pages.

Anatomy

  1. Sidebar--layout-sidebar-width (240 px), sticky, full height from 1024 px; a top bar below.
  2. Page headerTitle, description and actions; see page header.
  3. Page body--layout-margin at the sides (20 px, 32 px from 768 px), --space-10 below.

Sizes

One shell. The sidebar is 240 px, the detail panel 400 px, the form body at most 896 px (which is also the width of the centred card).

States

The shell has no interactive states; it has arrangements per screen state.

ArrangementClassUsed by
Default.appOverview, Runs, Sources, API, Settings, Not found
Split.app__main.app__main--splitArticles with an article selected
Bare.app.app--bareSign in (all five states), Access denied
Form body.page-body.page-body--formSettings
Centred body.page-body.page-body--centeredSign in, Access denied, Not found

Both themes

  • The sidebar is ink in both themes; in the dark theme it is one step darker than the canvas so it still reads as the frame.

Responsive behaviour

  • Below 1024 px: one column. The sidebar is a top bar with the navigation scrolling sideways; its footer is hidden.
  • From 1024 px: a two-column grid, sidebar 240 px and main minmax(0, 1fr).
  • Split: the detail panel is a 400 px sticky column from 1024 px and covers the screen below that. Between 1024 and 1535 px the table drops its optional columns to make room.
  • Bare ignores the grid at every width (.app.app--bare is two classes strong so it wins over the 1024 px rule); the centred card is capped at 896 px and starts --space-12 from the top.
  • The shell is at least 100dvh tall, so mobile browser chrome never clips it.

Theming

The shell has no colours of its own: the page shows --color-bg-canvas and the sidebar its shell tokens.

Accessibility

Role and pattern

Landmarks: the sidebar is an <aside> holding <nav aria-label="Primary">; the content is <main id="main">; a skip link comes first. The bare shell has only the skip link and <main>.

Keyboard

KeyAction
TabSkip link, then the sidebar (brand, six links), then the main column.
Enter on the skip linkMoves focus to #main.

Focus

On navigation the router moves focus to the new page's h1 so the title is announced. In the split arrangement, opening the panel moves focus into it and closing returns focus to the row.

Labelling

Each page has a unique <title> and one h1. The primary navigation is the only nav landmark and is labelled “Primary”.

Content

  • Every screen is one of the three arrangements; a new arrangement needs a mock first.
  • System pages (sign in, access denied, not found) say what happened and offer one way forward; see the empty and error states pattern.
  • Not found keeps the full shell, because the person is signed in and can navigate away.

Timeline

The steps of one run in order, each with its outcome, how long it took and what it produced.

Overview

The timeline shows a run's pipeline on the Runs screen: fetch, parse, classify, deduplicate, store, publish. It reads top to bottom and tells where a run went wrong.

  • Five step states: ok, warn, failed, running, skipped.
  • A connecting line joins the icons.

Anatomy

  1. StepA 20 px status icon on the connecting line.
  2. Name and timeLabel and a tabular duration, on one row.
  3. DetailA caption with the step's numbers; danger-coloured when the step failed.

Responsive behaviour

  • Fluid; name and time wrap onto two lines when the name is long.
  • The connecting line stretches with the step's height.

Theming

Icons take the status icon colours; a skipped step's icon is the emphasis border colour and its name is subtle.

Accessibility

Role and pattern

An <ol>: order is meaning. Each step's state is hidden text before its name (“Done with warnings: Fetch sources”).

Keyboard

KeyAction
—Not focusable. It is read in document order with the content around it.

Focus

Not focusable.

Labelling

The section heading (“Pipeline”) labels the list. While a run is in progress the running step's detail is a polite live region.

Contrast

Motion

None; the running icon does not spin. The status card carries the spinner.

Touch

Not interactive, so no target size applies.

Content

  • Step names are verb phrases: “Fetch sources”, “Classify relevance”, “Publish to API”.
  • Durations are m:ss; a step not run shows an em dash.
  • The detail states counts: “53 relevant · 6 held for review · 130 off-topic”.

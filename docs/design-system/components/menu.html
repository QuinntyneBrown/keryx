Menu

A short list of actions for one row, opened from its ••• button.

WCAG 2.2 AAStatus: stableAPG menu buttonBlock: .menu, .menu-anchor

Overview

Use a menu when a row has more actions than fit beside it. In Keryx that is the Sources table: edit, test, open the site, remove. Two actions or fewer stay as buttons in the row, as Revoke does in the API table.

  • Safe actions first, then a divider, then the destructive one in the danger tone.
  • A destructive item opens a confirmation dialog; it never acts at once.
  • The menu belongs to its anchor: it is positioned under the trigger, right-aligned, and closes when focus leaves it.

Anatomy

  1. Surface--color-bg-surface-raised, --radius-lg, --shadow-3, at least --layout-menu-min-width wide, --space-1 padding.
  2. Item--control-height-md tall, 14 px icon and label, --radius-md hover fill.
  3. DividerA hairline that separates the destructive group; role="separator".
  4. Danger item--color-danger-fg text and icon.

Variants

One variant: icon plus label, with an optional divider and danger item. Checkable items (aria-checked) and disabled items are styled for when a screen needs them.

  • Open: the trigger has aria-expanded="true" and keeps its hover fill.
  • Closed: the menu element is removed from the DOM, not hidden with CSS.

Responsive behaviour

  • The menu is right-aligned to its trigger, which sits in the last column, so it opens inwards at every width.
  • The table wrapper normally scrolls horizontally; while a menu is open it switches to .table-wrap--open so the menu is not clipped.
  • On touch devices items are 44 px tall. The menu does not become a bottom sheet: it has at most five items.

Theming

The surface is --color-bg-surface-raised, which is one step lighter than cards in the dark theme, so the menu reads as raised even where the shadow is hard to see.

Accessibility

Role and pattern

The WAI-ARIA menu button pattern: the trigger has aria-haspopup="menu" and aria-expanded; the list is role="menu" with role="menuitem" children. Build it on the CDK Menu.

Keyboard

KeyAction
Enter / Space / ArrowDownOn the trigger: opens the menu and focuses the first item.
ArrowDown / ArrowUpMoves between items, wrapping at the ends.
Home / EndFirst and last item.
Any letterType-ahead: moves to the next item starting with it.
Enter / SpaceActivates the item and closes the menu.
EscCloses the menu and returns focus to the trigger.
TabCloses the menu and moves on.

Focus

Focus moves into the menu when it opens and is kept inside by the arrow keys. On close it returns to the trigger; after Remove source it moves to the confirmation dialog, and from there back to the trigger or, if the row is gone, to the table.

Labelling

The menu takes the same label as its trigger (“Actions for Redeemed Run Club Toronto”). Each item is its visible text; the external item adds “(opens in a new tab)”.

Motion

The menu scales in from 0.96 over --duration-fast from its top-right corner. Under reduced motion it appears at once.

Touch

Items are 36 px tall, 44 px on touch devices, and span the menu's width.

Content

  • Verb first, as on buttons: “Edit source”, “Test fetch now”, “Remove source”.
  • Name the destination for an external item: “Open redeemedrun.ca”.
  • No more than five items. More than that is a screen, not a menu.

Issue card

One open problem on Overview: what went wrong, for which source, since when. The whole card links to the run it belongs to.

Overview

Issue cards fill the “Needs attention” rail. Each is a link, not a container with a button: there is exactly one thing to do with it, which is to open the run.

  • Tone by icon: error or warning.
  • Stacked 8 px apart in a list.

Anatomy

  1. Status icon16 px, danger or warning colour.
  2. BodyTitle (label), source (caption, muted, truncated), time (caption, subtle).
  3. ArrowA 14 px muted arrow: it opens inside the app.

Responsive behaviour

  • Full width below 1024 px, under the latest articles; in the 340 px rail from 1024 px.
  • The source line truncates; the title wraps.

Theming

A surface card with a decorative edge that darkens on hover.

Accessibility

Role and pattern

An <a> wrapping spans (no block elements or headings inside a link), in a <ul>.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
EnterOpens the run.

Focus

The shared ring (--focus-ring-width of --color-focus-ring, offset by --focus-ring-offset) appears on :focus-visible only, so a pointer click does not show it. It is ink in the light theme and volt in the dark theme, on the sidebar and on toasts.

Labelling

Hidden text gives the severity first: “Error: Feed returned 404, Redeemed Run Club Toronto, Today, 6:01 AM”.

Content

  • Title: what happened, in the system's words but readable: “Feed returned 404”, “Timed out after 30s”.
  • Source: the organisation's name.
  • Time: when it started, and the streak if there is one: “4 runs in a row · since Mon, 12:02 PM”.
